# ADR-0016: 元の予算と期限でWindowsを1台追加する

日付: 2026-10-21
状態: 採用（ユーザー承認済み。管理側の3台登録済み、新Windowsの取込・接続は未実施）
関連: REQ-003 / REQ-010 / REQ-011 / ADR-0015

## 判断

ユーザーは既存Mac・会社Windowsの2台に、Windowsをもう1台追加することを明示した。接続対象は指定3台に限定する。従業員ログイン不要、基本4機能と重要情報の隔離を維持し、元の累計10 USD、未確定3件の予約0.45 USD、2026-10-26 08:47:54 JSTの期限を全端末で共有する。新しい予算台帳・APIキー・Supabase projectは作らず、一度だけ実施した台帳移行を再実行しない。新たな未確定で新規送信を停止し、元の処理は再送しない。

3台目はそのWindows上で作る非エクスポート鍵に対する個別の端末証明書と、専用入口・専用DBの許可登録で識別する。既存端末の秘密鍵や証明書を複製して端末を追加しない。会社PCに管理者のChatGPT/Codex・個人Googleアカウントのログインを求めず、公開CSR・公開証明書だけを既存の手段で受け渡す。

## 理由と代替案

少数の指定PCで実際に使いながら改善する方針に沿う。既存2台を置換する方法では追加要求を満たさず、共有資格情報のコピーでは端末別の停止が難しくなる。WARP方式の再導入や新規契約を追加の前提にせず、現在の端末証明書方式を継続する。

## 準備と受入

入口コードに最大2台の上限があるため、先にローカルで最大3台へ変更し、従来1・2台の互換、3台目の認可、未登録の4台目・不正な証明書・直接URLの拒否を検証する。Cloudflareの許可一覧だけ先に3件にして既存端末の接続を壊さない。DBの端末行追加でも既存2行・予算・未確定・期限を照合して保持する。

新WindowsではTPMの状態とブラウザを確認し、公開CSR作成、証明書の発行・鍵への関連付け、管理側登録、専用ショートカット、ホームと終了時の入力消去の順に進める。初回はAI送信なしで接続確認する。TPMやTLSの互換性を既存Windowsと同一と推測しない。

追加契約・追加入金・予算増額・期限延長・一般公開・業務DBへの接続は許可に含まない。既存の未合格項目を今回の準備から合格に変更しない。[手順と進捗](../third-device-preparation-20261021.md)に実施範囲を記録する。
