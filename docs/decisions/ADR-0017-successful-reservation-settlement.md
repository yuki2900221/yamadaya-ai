# ADR-0017: 正常終了した処理の予約差額を解放する

日付: 2026-10-21
状態: 採用（ユーザー承認済み。反映・試験状況は下記報告を参照）
関連: REQ-010 / TRIAL-07 / ADR-0015 / ADR-0016

## 判断

ユーザーは、正常終了して料金計算を確認できた処理について、事前予約と計算額の差額をアプリの利用可能枠へ戻すことを求めた。送信前は最大額を予約し、正常終了かつ使用量から妥当な料金を計算できた分だけを精算する。送信中・結果不明・料金欠落・料金計算異常・予約額超過は予約を維持する。実請求との照合前であることは表示・報告上区別する。

監査用の当初予約額、使用量による計算額、操作ID・入力ハッシュ・状態を削除やゼロ化で書き換えない。全端末共通の利用可能枠計算と送信前の上限判定を同じ式にし、DBの予算行ロック下で競合を防ぐ。未確定の行を正常終了へ変更して利用枠を増やさない。

## 理由と代替案

これまでの集計は、成功後も予約額と計算額の大きい方を累積し、実際の利用量より早く試用枠を消費していた。成功と料金計算を確認した分の差額を解放すれば、同じ予算内で現場試用を継続できる。すべての予約を解放する方法は課金不明の費用を見落とすため採用しない。台帳のリセットや、新しい予算枠の作成もしない。

## 維持する条件

指定3台・従業員ログイン不要・元の累計10 USD・元期限2026-10-26 08:47:54 JSTを維持する。元の未確定3件の予約計0.45 USDは解放せず、同じ処理は再送しない。新たな未確定で新規送信を停止する。追加AI実行・追加入金・新規契約・権限拡大をこの判断に含めない。
