## 実装の選定理由

- **モデルとAPI**：前段で実測した `gpt-6-luna` と `gpt-image-2.5-flare-2026-09-08` を維持し、新しいSDK・別AI契約・自動fallbackを追加しない。既存の小さいAPI境界を再利用して変更範囲を抑える。[Lunaの公式仕様](https://developers.openai.com/api/docs/models/gpt-6-luna)、[Flareの公式仕様](https://developers.openai.com/api/docs/models/gpt-image-2.5-flare)。今回、新モデルの品質比較を実施したわけではない。
- **テキスト・検索**：Responsesは `store:false`、出力上限あり。Web検索はチャットで明示選択した1回だけ許可する。他のツール・モデル・未知の非ゼロ料金メーターは成功扱いにせず、自動再送しない。
- **runtime**：mockは実AIキーを参照しない。liveは専用project、固定の入口／上流、別DB login／schema、private画像bucketを照合する。キー・専用project・元期限の準備が不足すれば、予約・API送信の前に拒否する。
- **保存と権限**：認証と費用制御はサーバー側で強制する。ブラウザにDB資格情報やAPIキーを渡さず、管理操作の経路を作らない。文章・会話・入力写真は永続DBへ保存せず、画像は既存の期限付きprivate保存と認証付きchunk取得を使う。
- **POP**：情報入力→提案確認→全体画像→PDF保存を維持。用紙と入力済み情報の制約を適用し、確認事項が空でも掲載コピーへ操作案内を混ぜない。画像中の日本語・価格・商品外観は、実出力を人が確認する。
