# Macの接続拒否の調査（2026-10-23）

## 範囲と現時点の判定

ユーザーから、このMacでも試用画面を開けるようにする調査・修正の指示を受領した。指定3台・従業員ログイン不要・元の利用期限と予算を維持する。今回の調査では追加のAI実行・追加契約・課金を行わない。

**専用Chromeから、本人が初回のホーム表示と、再読み込み・閉じて再開した両方で「AI接続済み」になることを確認した。この専用起動方法でMacの試用アクセスは復旧した。** 既存のMac証明書を使い、普段のChromeと分けた専用プロファイルでQUIC無効・TLS 1.2を指定する起動方法を用意した。通常ChromeやCloudflare全体のTLS設定は変更していない。

先行のゲストモードではホームと「AI接続済み」を1回確認したが、閉じて開き直した2回目はHTMLの取得後に読み込み中で止まり、CSS・JavaScript・マーク画像が403になった。ゲストモードや、単に新規プロファイルを作る方法を、再現性のある解決策としては扱わない。

curlの初回の証明書指定では、MultiSSLの既定バックエンドが証明書名をファイルとして扱い、ローカル読込エラーで終了した。SecureTransportを明示した実接続試験とは区別し、HTTPの試験件数やサーバー拒否の証拠へ加算しない。自動再試行・リダイレクト・証明書検証無効化は行っていない。

## 変更していない境界と残件

- 指定3台の制限、従業員ログイン不要、元の予算・保留分・期限を維持した。今回、費用台帳の再集計や未確定処理の再送はしていない。
- ローカルの切り分けではUIから同期しないChromeプロファイルを1件作り、その後、起動ファイル専用のユーザーデータ領域を別に1件用意した。既存プロファイルの削除やChrome全体の終了はしていない。前述の「プロセス1件」は後者の専用プロファイルに一致した起動プロセス数であり、Mac内の全プロファイル数ではない。
- 証明書・鍵・Root信頼・Chromeの認証ポリシー・Cloudflareの認証/WAF/TLS設定・業務DNSは変更していない。管理画面のログインは、従業員向けアプリのログイン不要とは別の管理者操作である。
- 追加AI実行・新規契約・予算増額は0。今回の「AI接続済み」はホームでの接続状態表示であり、課金を伴うAI実行成功の証拠ではない。

Macの限定試用は、本人確認済みの専用起動ファイルから再開できる。HTTP/3と接続再利用、Chromeのモードごとの証明書提示、静的ファイル取得時の拒否の根本原因は引き続き未確定で、複数の互換指定を同時に使った今回の成功だけから原因を1つに断定しない。通常Chromeでの安定接続、Chrome全体の終了・OS再起動、今回の経路での追加AI実行・基本4機能の再試験は未実施。許可端末の追加や証明書検証無効化は行っていない。

## Mac専用の接続試験用起動

`tools/device-cert/mac-trial-chrome.command` は、標準の場所にある既存Chromeを専用のユーザーデータ領域で起動する。普段のChromeのタブ・プロファイルは終了・削除せず、Googleアカウントへログインしない。プロファイルの保存先はローカルの `~/Library/Application Support/Yamadaya AI Chrome Trial` で、作成時の権限は700。秘密鍵・証明書・APIキーはコピーしない。

今回の限定試験ではQUICを無効にし、TLS 1.2を指定する。サーバー証明書の検証、既存Macのクライアント証明書、Cloudflareとアプリの3台制限は維持する。この起動ファイル自体はAIを送信しない。この起動設定での初回・再読み込み・専用窓再開の接続成功は本人確認済みだが、実際に交渉された通信方式は独立未測定で、HTTP/3だけが拒否原因という結論にはしない。

操作ツールではTerminalへのアクセスが安全上許可されなかったため、別の方法でその制限を迂回せず、Finderに起動ファイルを選択して利用者へ手動起動を依頼した。既存Chrome全体の再起動、Root信頼追加、認証ルールの緩和は依頼していない。

起動方法の根拠はChromiumの[ユーザーデータ領域の公式説明](https://chromium.googlesource.com/chromium/src/+/HEAD/docs/user_data_dir.md)と[起動引数の定義](https://chromium.googlesource.com/chromium/src/+/HEAD/chrome/common/chrome_switches.h)。Cloudflareの[TLSセッション再開に関する制約](https://developers.cloudflare.com/learning-paths/mtls/mtls-app-security/related-features/)は原因候補の説明であり、このMacでの原因確定の証拠ではない。
