# 設定・運用

## 共用PCへ渡す前

1. Node.js 24系で依存を固定してインストール。
2. `npm test` / `npm run build` / `npm run check:public` を実行。
3. 管理PCで専用Project・最小権限・期限付きキーを準備し、費用の上限を承認。
4. `.env.shared.local` を作り、所有者だけ読める0600にする。
5. ビルド済み配信を起動。開発サーバーや他システムを公開しない。

```text
APP_MODE=live
TRIAL_BUDGET_USD=10
ENABLE_SEARCH=true
OPENAI_PROJECT=your_test_project
OPENAI_TEXT_KEY=your_restricted_key
OPENAI_IMAGE_KEY=your_restricted_key
```

```sh
node --env-file=.env.shared.local server/index.mjs
```

上限は今回承認された範囲まで。既存台帳と異なる予算では起動を拒否します。台帳を削除して上限をリセットしないでください。秘密キーをチャット・ソース・公開リポジトリ・画面の入力フォームへ貼りません。

## 終了・再起動

利用者は「利用を終了」を押します。未送信の入力や結果は消去されますが、実行中のAPIや課金は取り消せない場合があります。明示的に保存したファイルはPCのダウンロード先から別途片付けます。

サーバーを終了するとメモリの会話・画像は失われます。費用台帳は残ります。送信中に再起動した処理を再実行せず、課金未確定の確認を管理PCで行ってください。キーの期限・権限・残高は別途確認し、エラー時に自動チャージや本番キーの流用はしません。

## リモート試用

この版は同じPCのブラウザで使うローカル配備が既定です。別PCからの利用や公開URLには別の配備・端末認証が必要です。GitHubでのソース公開と、実AIを使うWebアプリの外部公開は別の操作です。

`scripts/admin.mjs`は費用台帳を読むだけです。課金確認の根拠なくunknownを成功/無料へ変更したり、台帳を削除して再開しないでください。1回限定の承認例外は管理PCの非公開ファイルに指定したID・入力ハッシュ・期限へ固定されます。Web画面からは作成・変更できません。

元の未確定1件を残した再開は管理PCの期限付き確認ファイルに限ります。別の未確定が増える、期限が切れる、同じ未確定入力を再送する場合は拒否します。この承認ファイルも公開・ブラウザ配信しません。
