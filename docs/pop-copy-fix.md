# POPの確認文混入を修正

2026-10-19。利用者から、提案画面の「コピー」にある「内容をご確認ください。」が生成POPへ掲載されるとの報告を受けた。

## 原因

入力にない特徴を自動採用しないため、提案のコピーを元情報の行に制限していた。しかし許可できないコピーの代替値が、確認用の文「内容をご確認ください。」だった。これを候補にも追加し、画像APIへ「利用者が確認したコピー」として渡していた。確認事項と掲載文章を混同した実装上の不具合。

## 修正

- コピーの代替値を空文字にし、UIでは「入れない」と表示する。
- 欄名を「キャッチコピー（任意）」にし、POPに載る文章だと分かる説明を付ける。
- 提案のSchemaとサーバーの検査で、入力済みの行または空文字だけを許可する。確認事項は別の表示欄に残す。
- 画像APIへ渡す直前にも元情報との完全一致を検査する。古い画面に残った確認文も、入力由来でなければ掲載コピーから除く。空の場合はコピーの項目自体を画像プロンプトへ入れない。
- 利用者が元情報へ明示的に記載した行は保持する。特定の文言を一律に禁止する方式にはしない。

用紙・元情報・中点・空白・参照写真・予算・未確定処理・モデル・生成枚数の条件は維持する。既存のPhase 0アプリは変更せず、現在のshared-webだけを修正した。

## 検証

自動試験80件、失敗0。追加した11件で、空コピーの正常終了、旧確認文の除去、入力行の完全保持、4用紙、通常生成と写真付き編集の送信内容、長い画像入力、費用と予約の維持を確認した。外部APIは模擬応答に置き換えた。

実ブラウザでは、確認文を返す無課金の模擬プロバイダーを使い、提案画面が「入れない」へ置換すること、確認文が候補にないこと、入力した中点・連続空白の値を保持すること、選択後に画像処理へ渡すcopyが空文字になることを確認した。A4横と元情報も保持した。

証拠は非公開の`results/tests-pop-copy-fix.txt`、`results/pop-copy-dispatch.json`、`results/pop-copy-none.png`。公開ソースに生成物や実行台帳は含めない。

追加の有料API・実画像生成・課金設定・クラウド操作は0。実モデルによる修正後の描画品質は再試験していない。すでに作成済みの画像に焼き込まれた文字は、この修正だけでは消えない。修正版を利用するには、作成済み画像を保存してから画面を再読み込みする。
