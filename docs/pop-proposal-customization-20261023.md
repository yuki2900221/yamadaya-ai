## 改善した内容

「見出し・キャッチコピーを選ぶと何が変わるか」「選ばないと何が残るか」を、選択欄の説明と元情報の横の一覧に表示する。選び直さなければ現在表示中の内容で作成することも明示した。見出しは選んだ行を大きく目立たせる指定、キャッチコピーは補助的な文章として添える指定とする。どちらにも「入れない」を用意した。

「入れない」は追加の文字指定を省く操作であり、元の商品情報から商品名・価格・説明を削除する操作ではない。同じ行を見出しやコピーにも選んだ場合、文字を二重に掲載せず強調方法へ反映するよう画像モデルへ指示する。掲載文は従来どおり、入力済みの行と許可済みの中立見出しから選ぶ。画像送信直前にも見出し・コピーを再検査する。

配色・構図の4種類をベースとして残し、「自由に指定（定型を使わない）」と、最大500文字の「デザインの希望」を追加した。色・余白・配置・装飾などを指定できる。定型と追加指定の配色・構図が競合する場合は追加指定を優先する。自由指定かつ希望が空欄の場合は、選んだ雰囲気に合わせてAIへ任せる。

デザイン指定は掲載文字や商品情報と分離して画像生成要求へ渡す。用紙・商品情報・価格・期限を変更する指示は採用しないように指示し、A4/A3縦横の用紙と送信画像サイズの決定は既存の固定パラメータで行う。商品情報を変える場合は、画面の「情報を修正」から元情報を編集する。

見出し・コピー・配色・構図・希望を変えたら、画像送信の確認チェックを解除する。編集だけではAPIを呼び出さず、明示的に作成ボタンを押した操作だけを送信する。下書きはデザインの希望と、空文字を含むベース選択を保存・復元する。旧version 1下書きも受け付けるが、保存済みのAI提案・確認済みフラグは信用せず、提案確認へ戻す。写真を下書きへ含めない従来の扱いも維持する。

## 自動試験

`shared-web/`で`npm test`を実行し、**360件中358成功・失敗0・既定skip2**。`npm run build`も成功した。skip2を今回実施済みの件数へ含めず、以前の別実行TLS試験を今回の新規結果として扱わない。

今回の追加10件は、共有契約・画像要求の7件と下書きの3件である。主な確認範囲は次のとおり。

- 空見出し、元情報の完全な行、日本語・中点・空白・否定表現の保持。未入力の見出しや部分一致文字列の不採用。
- 任意のデザイン希望について空・500文字の許可、501文字や不正な型の拒否。POP画像作成以外への混入と未確認送信の拒否。
- A4/A3縦横4種類で、ローカル・hostedの偽プロバイダーを通した用紙と画像サイズの保持。自由指定で4種類の定型へ自動的に戻らないこと。
- デザイン希望のJSON文字列への分離、商品情報と固定用紙の維持、見出し・コピーの省略／強調に関する送信内容。
- 4用紙と自由／定型選択での下書き保存・復元。旧下書きの互換、不正なデザイン選択・過大入力の拒否。

既存のPOP回帰試験では、4用紙の通常画像生成・商品写真を伴うFormData送信、空コピー、元情報・用紙の保持も偽プロバイダーで確認した。hosted側は同じ共有プロバイダーを使用する。これらは外部APIの実行結果ではない。
