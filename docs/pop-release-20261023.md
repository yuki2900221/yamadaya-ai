# POP提案の改善を既存3台限定試用版へ反映

日付: 2026-10-23（日本時間）
状態: ユーザー承認済み、配備前確認中。配備完了・更新後合格とはまだ判定しない。

## 承認範囲

ユーザーは[ローカル改善](pop-proposal-customization-20261023.md)を確認し、既存の3台限定試用版への反映を承認した。対象はPOP提案画面の見出し・キャッチコピーの説明、「入れない」の扱い、配色・構図の自由指定と最大500文字のデザイン希望、下書き保存・復元である。[ADR-0018](decisions/ADR-0018-pop-design-customization.md)を判断の正本とする。

既存Vercel `yamadaya-ai-trial`を更新し、指定3台・従業員ログイン不要・元の合計10 USD・未確定3件0.45 USDの保留・元期限2026-10-26 08:47:54 JSTを維持する。Cloudflareの端末認証条件・許可端末・Worker、DBの権限・既存台帳・予約精算、サーバーの秘密設定を変更する作業には広げない。追加AI実行、追加入金、新規契約、課金設定の変更は行わない。

## 配備前に確認すること

- ローカルの自動試験・ビルドと、公開許可リストの秘密検査を確認する。以前のローカル実ブラウザ結果と今回の配備後確認を区別する。
- 隔離したBuild Output API bundleを作り、現在の対象ソースと一致することを照合する。秘密・台帳・写真・生成物・管理用ファイルを含めず、全ルートで既存のgateway proof検証を行う構成を保つ。
- 実AI用providerコードを含む既存試用版のため、bundle検査の明示オプション`--allow-live-provider`を使用する。コードを含むこととAIの実行を区別し、検査でAPIを呼び出さない。
- 既存team・project・Production・固定alias・戻し先をメタデータで照合する。秘密値を読み出さず、設定を再保存しない。

正常終了分の予約精算は既に適用したDB関数を使用する。今回、migrationの再実行・台帳の再import・初期化は不要であり実施しない。[精算結果](reservation-settlement-20261021.md)は過去の実照合として扱い、今回の残高照会結果へ流用しない。

## 配備後に確認すること

Macの専用Chromeから、従業員ログインなしのホーム・基本画面・新しい配信JS/CSSを確認する。提案の取得とPOP生成はAI実行になるため実施せず、接続確認を生成品質の確認とは扱わない。

固定Vercel直接URL、固有deployment URL、証明書なしのCloudflare入口、端末情報を偽るヘッダー等の拒否を、既存認証を緩めず再確認する。使用するのはAI処理を開始しない確認だけとする。通常のセッション／認証nonceの読み書きと、AIジョブの送信を区別する。

会社Windows2台での更新後実操作、実モデルによる希望の反映、生成後PDFの再検査は未実施項目として残す。Macで配信更新を確認できても全3台の実操作を合格にしない。

## 戻し方

更新前のProduction deploymentを保持し、回帰があれば同じ既存projectの元deploymentへ戻す。具体的な戻し先と更新先は配備時のメタデータで記録し、戻した後も固定alias・正規Mac接続・直接URL拒否を確認する。過去の既知不具合や利用中の画面状態まで復元できるとは案内しない。
