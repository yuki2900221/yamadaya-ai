# 正常終了分の予約精算と未確定分の扱い

日付: 2026-10-21
判断の正本: [ADR-0017](decisions/ADR-0017-successful-reservation-settlement.md)

## 問題と修正

旧集計は、各処理で予約額とusage計算額の大きい方を、成功後も費用枠として保持していた。2026-10-21 11:04 JSTの照会では、usage計算額0.256690 USDに対して予約計5.590000 USD、残り枠4.410000 USDとなっていた。この予約はOpenAIの引落し額・クレジット残高ではなく、アプリ内の上限管理である。

正常終了し、料金が欠落せず妥当な範囲と確認できた行は計算額だけを消化する。送信中・未確定の行は予約額と判明している料金の大きい方を保持する。元の予約・料金・状態・操作ID・入力ハッシュは監査のため残し、集計方法を変更する。表示用usageと送信前の予算判定は同じ式を使用する。

## 「課金が未確定の保留分」とは

アプリがAPIへ送信した後、正常な応答や完全な料金情報を確認できず、処理結果や課金の有無・金額を確定できなかった履歴である。通信切断等では、画面で結果を受け取れなくても提供側で処理が進んでいる可能性がある。エラー表示だけから無料と判断せず、確認できるまでアプリ内で予算を取り置く。

元の保留は画像生成1件の0.35 USDと、Web検索2件の各0.05 USD、計3件0.45 USD。0.45 USDの請求が確定した意味ではない。画像処理の通信・応答不明と、検索の応答／料金確認エラーを起点とする。[運用記録](operations.md)と[検索再試験記録](all-features-week-trial.md)を参照。過去の検索エラーの生応答がないため、その2件の根本原因を確定済みとはしない。

ユーザーはこの3件の保留を残した新規試用を承認済み。今回の成功分精算でも、元unknown行を成功・無料へ変更せず、元の処理を再送しない。後続試験の成功を元の課金解決へ流用しない。usage計算額には未確定行に残った既知の料金が含まれる場合があるため、総額と0.45 USDを機械的に足して正確な残額を断定しない。

2026-10-21 13:13 JST、既存専用trialの最小権限接続・厳格TLSで現在のruntime定義とusageを確認し、短いトランザクションをロールバックした。旧集計の該当式はruntime内の2箇所。関数所有者・SECURITY DEFINER・search_path・既存ACLを確認した。集計は46ジョブ、usage計算0.256690 USD、予約5.590000 USD、uncertain3、paused=false、合計10 USD・元期限のまま。AI実行やコミットされるDB変更はない。

## 試験・反映結果

ローカルSQLiteと専用クラウドPostgresの集計を修正した。SQLiteは妥当な整数の料金を持つ正常終了だけを精算し、不正な成功情報・欠落・予約超過を未確定として保持する。完了済み行の書換えも拒否する。クラウドは既存の正常終了判定を維持し、usageと新規予約判定の2式だけを同じ精算式へ変更した。元の監査用holdを減額していない。凍結済み旧ローカル台帳は起動・変更・再importしていない。

- 通常の全自動試験：350件中348成功、失敗0、HTTP/HTTPS実listenの既定skip2。
- 上記skipを有効にした別実行：ローカルTLS試験14/14成功、失敗・skip0。単一実行で350/350と表現しない。
- 移行SQLのダミーPGlite試験13/13成功。成功分の差額解放、同じ枠での次の送信、共有上限、未確定／費用超過の保持、重複完了拒否、元snapshotの検査、失敗時ロールバックと逆移行を含む。独立接続による実Postgres競合の再試験ではない。
- 公開対象103ファイルの秘密検査は最終文書を含め検出0。実行用SQL、台帳・資格情報・UI確認ファイルは非公開の実行領域へ分離した。ソースのGitHub反映は今回未実施。

ユーザーは精算用SQLだけの一時的なクリップボード読取をSupabaseへ許可した。SQL Editorの対象projectを照合し、入力全文を読み戻して原本と末尾改行以外が一致したことを確認してから実行した。既存の関数定義のハッシュを前提に、対象2式だけを置換する専用移行を使用した。6テーブルの全行、schema・関数所有者・ACL・SECURITY DEFINER・search_path・他の関数定義の不変をトランザクション内で検査した。処理中・新たな未確定・元の3台／10 USD／期限／unknown集合の差分があれば実行を拒否する。追加権限の付与やデータ行の更新はない。
